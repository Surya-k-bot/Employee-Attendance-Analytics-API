# REVIEW.md

Defects identified in the starter implementation and corrected in `app/main.py`:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It floors elapsed minutes before applying the 10-minute grace test, so a punch 10 minutes and 1 second late is incorrectly treated as on time. It also anchors the shift start to the punch's local date rather than the IST attendance date. | For shift 09:30, 09:40:01 must yield 10 late minutes; test a UTC/IST boundary and an overnight shift. | Compare elapsed seconds to 600, calculate against an IST shift start built from the attendance date, and floor only the reported minutes. |
| 2 | `compute_work_hours` | Python `round()` uses ties-to-even and float arithmetic, contrary to half-up rounding. | Test durations whose hours land exactly at a two-decimal half-way value. | Use `Decimal` with `ROUND_HALF_UP` after truncating instants to seconds. |
| 3 | `compute_overtime` | It counts any positive overtime instead of requiring 30 minutes, mishandles overnight shift-end dates, and subtracts an aware time from a naive one. | Test +29:59 and +30:00 after shift end, plus a 22:00–06:00 shift. | Build shift end from attendance date in IST (next date for overnight), normalize to UTC, and apply the 30-minute threshold. |
| 4 | `/health` | It always reports ready, even when MongoDB is unreachable. | Stop MongoDB and request `/health`; starter still says `ok`. | Ping MongoDB and return 503 on database failure. |
| 5 | `create_employee` | Duplicate detection is check-then-insert and can race; there is no guaranteed unique index. `created_at` uses naive local time. | Concurrently create the same code or run under a non-UTC host timezone. | Add a unique `emp_code` index, map duplicate-key errors to 409, and store UTC server time. |
| 6 | `list_employees` | Pagination skips the first page, filtered totals count the entire collection, results are not sorted, and query bounds are unchecked. | Request page 1, filter by department, then try page 0 or page_size 101. | Count with the same filter, sort by code, use `(page - 1) * page_size`, and validate pagination. |
| 7 | `punch_in` | Unknown codes cause a server error; status and timestamp inputs are insufficiently validated; a supplied zero timestamp silently becomes “now.” | Punch for an unknown employee; send `ABSENT`, seconds, float, string, or zero. | Return 404, restrict status, strictly validate epoch milliseconds, and distinguish omitted timestamp from invalid supplied values. |
| 8 | `punch_in` | Host-local `fromtimestamp` and direct date selection violate IST/overnight date rules and retain milliseconds. A check-then-insert permits concurrent duplicates, and the response leaks a generated id. | Test near UTC midnight, overnight shifts, nonzero milliseconds, concurrent same-day requests, and response keys. | Normalize and truncate epoch values, derive the IST attendance date, rely on a unique `(emp_code, date)` index for atomic conflict detection, and serialize only contract fields. |
| 9 | `list_attendance` | It loads and sorts the complete collection in Python, violating the scale requirement; tie ordering is unspecified. It returns `_id` and misses legacy defaults. | Use a large dataset, same-date employees, or a seeded record without `history`/`half_day`. | Filter/count/sort/page in MongoDB, sort date descending then code ascending, and explicitly serialize contract fields with legacy defaults. |
| 10 | `list_attendance` | Invalid/reversed date ranges and pagination bounds are not rejected. | Request `date_from > date_to`, malformed dates, or out-of-range page values. | Parse calendar dates and apply contract validation before querying. |
| 11 | Application | Punch-out, regularization, all analytics endpoints, and explain are missing. | Request any operation marked “You” in the assignment brief. | Implement those endpoints, including MongoDB aggregations and execution-stat explain support. |

Not defects: using `emp_code` as the employee identifier and `(emp_code, date)` as the attendance natural key are deliberate contract requirements; MongoDB `_id` must remain internal. Exact department equality filtering was also appropriate, though the starter's count, ordering, paging, and execution strategy were not.
